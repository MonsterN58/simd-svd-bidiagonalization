\section{实验背景与实验目标}

本次实验我选择的是矩阵 SVD 算子方向。相比之前的单机程序，MPI 版本最明显的区别是各个进程之间不能直接共享矩阵数据，矩阵的广播、归约、子任务分发和结果回收都需要通过 MPI 通信完成。因此，这次实验的重点不只是把循环拆开并行执行，还要考虑任务划分是否合理、通信开销是否过大，以及进程数增加后是否真的能带来加速。

我的实现主要分成两个阶段。第一阶段是使用 Householder 变换把原矩阵化为上二对角矩阵，同时累积左右正交矩阵；第二阶段是在上二对角矩阵上进行 Golub-Kahan 隐式迭代，最后得到奇异值矩阵。对应关系为
\[
A \approx U S V^T.
\]

根据 SVD 选题的要求，本实验中主要完成了以下内容：
\begin{enumerate}
  \item 实现了 SVD 分解的 MPI 版本，包括上二对角化和 GKH 迭代；
  \item 在 GKH 阶段实现了主从式任务池，由 rank 0 负责分发活动子矩阵，其他进程负责计算；
  \item 修改了原来的迭代方式，不再每轮反复扫描所有子矩阵，而是让 worker 对非 $1\times1$ 子矩阵连续迭代到可以再次分裂；
  \item 在上二对角化阶段保留了 SIMD 优化，对连续向量点积和向量更新使用 AVX/SSE；
  \item 测试了 1、2、4、8 进程（单节点）及 2 节点 8 进程下不同规模矩阵的正确性和运行时间，并分析加速效果不佳甚至性能下降的原因。
\end{enumerate}

需要说明的是，本实验没有实现 MPI 与 Pthread/OpenMP 的混合并行，主要完成的是 MPI 多进程并行和 SIMD 数据级并行的结合。对于 Pthread/OpenMP 的部分，报告中只做一些可能的改进方向讨论。

\section{SVD 算法理论}

\subsection{SVD 分解定义}

对于一个实矩阵 $A\in \mathbb{R}^{m\times n}$，其中 $m\ge n$，SVD 分解可以写成
\[
A = U\Sigma V^T.
\]
其中 $U\in\mathbb{R}^{m\times m}$ 和 $V\in\mathbb{R}^{n\times n}$ 都是正交矩阵，满足
\[
U^TU=I,\qquad V^TV=I.
\]
$\Sigma\in\mathbb{R}^{m\times n}$ 是对角型矩阵，对角线上的非负数称为奇异值，通常按照从大到小排列：
\[
\sigma_1\ge \sigma_2\ge \cdots \ge \sigma_n\ge 0.
\]

从理论上看，SVD 可以通过 $A^TA$ 的特征值分解得到，因为
\[
A^TA = V\Sigma^T\Sigma V^T.
\]
但是直接构造 $A^TA$ 会放大条件数，数值稳定性比较差。因此我的代码采用两阶段方法：先做上二对角化，再对二对角矩阵做 GKH 迭代。

\subsection{Householder 上二对角化}

第一阶段是把原矩阵 $A$ 化成上二对角矩阵 $B$。所谓上二对角矩阵，就是只有主对角线和第一条上对角线可能非零。其形式大致为
\[
B=\begin{bmatrix}
d_1 & e_1 & 0 & \cdots & 0\\
0 & d_2 & e_2 & \cdots & 0\\
\vdots & \ddots & \ddots & \ddots & \vdots\\
0 & \cdots & 0 & d_{n-1} & e_{n-1}\\
0 & \cdots & \cdots & 0 & d_n
\end{bmatrix}.
\]

Householder 变换的基本形式是
\[
H = I - \beta vv^T, \qquad \beta = \frac{2}{v^Tv}.
\]
因为 $H$ 是正交矩阵，所以使用 Householder 变换不会改变矩阵的奇异值。在第 $k$ 步中，我先对第 $k$ 列从 $k$ 行开始的向量构造 Householder 反射，消去该列下方元素；然后如果 $k<n-2$，再对第 $k$ 行右侧向量构造右 Householder 反射，消去该行更右侧元素。不断重复后即可得到
\[
B = U^T A V,
\]
也就是
\[
A = U B V^T.
\]

\subsection{Golub-Kahan 隐式迭代}

第二阶段是对上二对角矩阵 $B$ 做 Golub-Kahan 迭代。该过程本质上相当于在 $B^TB$ 上做隐式 QR 迭代，但为了避免显式形成 $B^TB$，程序直接在二对角矩阵上通过 Givens 旋转进行 bulge chasing。

Givens 旋转的形式为
\[
G=\begin{bmatrix}
c&s\\
-s&c
\end{bmatrix},
\]
它可以把二维向量中的某个分量消成 0。一次 bulge chase 的基本过程是：
\begin{enumerate}
  \item 根据当前活动块右下角的 $2\times2$ 子问题计算 Wilkinson shift；
  \item 在活动块左上角引入位移后的旋转；
  \item 交替使用右 Givens 和左 Givens，把新产生的 bulge 从左上角追赶到右下角；
  \item 当某个上对角元素足够小时，将其置零，从而把原问题分裂成更小的子问题。
\end{enumerate}

我的代码中收敛判断使用类似
\[
|B_{k,k+1}| \le \varepsilon\bigl(|B_{k,k}|+|B_{k+1,k+1}|+1\bigr)
\]
的准则。当上对角元素满足该条件时，就认为该位置可以断开。最后把所有上对角元素清零，并将对角线元素取非负、排序，得到最终奇异值。

\section{代码实现与并行化思路}

\subsection{程序整体结构}

本实验代码主要由以下文件组成：
\begin{itemize}
  \item \texttt{main\_mpi.cpp}：MPI 版本测试入口，负责初始化 MPI、构造测试样例、统计运行时间并检查正确性；
  \item \texttt{bidiag\_mpi.cpp}：MPI 并行上二对角化，实现 Householder 阶段；
  \item \texttt{gkh\_mpi.cpp}：MPI 并行 GKH 迭代，实现主从式任务池和子矩阵动态分配；
  \item \texttt{matrix.h}：矩阵类与基础矩阵运算；
  \item \texttt{givens.h}：Givens 旋转生成函数。
\end{itemize}

主程序中每个测试样例都会先调用
\begin{lstlisting}[language=C++]
Matrix B = to_bidiagonal_mpi(A, U, V);
const bool converged = gkh_svd_from_bidiagonal_mpi(U, B, V, 6000, 1e-12);
\end{lstlisting}
之后在 rank 0 上计算重构误差、正交误差、对角结构误差、排序误差等指标。主要检查公式为
\[
\|A-U S V^T\|_F,
\]
以及
\[
\|U^TU-I\|_F,\qquad \|V^TV-I\|_F.
\]
这样可以同时验证分解结果的数值正确性和正交矩阵的稳定性。

\subsection{上二对角化阶段的 MPI 实现}

在 \texttt{to\_bidiagonal\_mpi} 中，rank 0 首先检查矩阵规模，并将矩阵尺寸广播给其他进程。由于 MPI 各进程内存独立，为了简化实现和保证正确性，每个进程都保存一份完整的 $B,U,V$。初始矩阵 $B$ 由 rank 0 广播给所有进程。

左 Householder 阶段中，计算
\[
w = v^T B_{k:m,k:n}
\]
是一个可以按行划分的部分。我的实现将行区间静态分配给各进程，每个进程计算自己的 \texttt{w\_local}，再通过 \texttt{MPI\_Allreduce} 得到全局 $w$。然后各进程只更新自己负责的行。为了让所有进程的 $B$ 保持一致，又使用一次归约同步更新后的矩阵块。

核心代码思路如下：
\begin{lstlisting}[language=C++]
int total_rows = m - k;
int rows_per_proc = total_rows / mpi_size;
int remainder = total_rows % mpi_size;
int my_start = rank * rows_per_proc + std::min(rank, remainder);
int my_count = rows_per_proc + (rank < remainder ? 1 : 0);

std::vector<double> w_local(n - k, 0.0);
for (int i = my_start; i < my_start + my_count; ++i)
    add_scaled_contiguous(w_local.data(), &B.at(k + i, k), n - k, v[i]);

MPI_Allreduce(w_local.data(), w.data(), n - k, MPI_DOUBLE,
              MPI_SUM, MPI_COMM_WORLD);
\end{lstlisting}

右 Householder 阶段与左侧类似，只是方向变为对列或行的更新。由于矩阵规模较大时 Householder 更新的数据量较多，这一部分理论上具有一定并行潜力；但同时它也需要频繁同步矩阵块，所以通信开销也比较明显。

\subsection{SIMD 合并实现}

实验要求中还提到需要合并之前 SIMD 的内容。我的上二对角化代码在连续内存向量的点积和加权更新中加入了手写 SIMD。比如 \texttt{dot\_contiguous} 在支持 AVX 时一次处理 4 个 double：
\begin{lstlisting}[language=C++]
__m256d acc = _mm256_setzero_pd();
for (; i + 3 < len; i += 4)
{
    const __m256d va = _mm256_loadu_pd(a + i);
    const __m256d vb = _mm256_loadu_pd(b + i);
    acc = _mm256_add_pd(acc, _mm256_mul_pd(va, vb));
}
\end{lstlisting}

对应的向量更新函数 \texttt{add\_scaled\_contiguous} 也使用 AVX/SSE 做批量更新。这样做的好处是 Householder 阶段中大量出现连续向量点积和 \texttt{dst += alpha * src} 操作，SIMD 可以降低单进程内部的计算时间。不过在 MPI 版本里，SIMD 的收益会受到通信和同步影响。如果通信占比变大，单纯加速局部计算并不能线性反映到总时间上。

\subsection{GKH 迭代的主从式任务池}

根据实验要求，需要实现主从式结构。我的 \texttt{gkh\_mpi.cpp} 中 rank 0 是 master，其他 rank 是 worker。通信 tag 设计如下：
\begin{itemize}
  \item \texttt{TAG\_REQUEST}：worker 向 master 请求任务；
  \item \texttt{TAG\_TASK}：master 向 worker 发送子矩阵任务；
  \item \texttt{TAG\_RESULT}：worker 将计算完成的子矩阵返回 master；
  \item \texttt{TAG\_TERMINATE}：master 通知 worker 结束。
\end{itemize}

master 首先对当前上二对角矩阵进行扫描，把所有非 $1\times1$ 的活动块加入任务池。每当 worker 空闲时，它会发送请求。如果任务池非空，master 就提取对应子矩阵以及相关的 $U,V$ 列，打包发送给 worker。worker 完成迭代后再把结果发送回来，master 写回全局矩阵，并重新检查这个范围是否分裂成新的活动块。

任务数据结构如下：
\begin{lstlisting}[language=C++]
struct SubMatrixData
{
    int l, r;
    int sub_size;
    int m, n;
    std::vector<double> B_sub;
    std::vector<double> U_cols;
    std::vector<double> V_cols;
};
\end{lstlisting}

这里不仅要传 $B$ 的子块，还要传 $U$ 和 $V$ 的相关列。原因是 Givens 旋转不仅改变 $B$，还必须累积到 $U,V$ 上，否则最后虽然奇异值可能正确，但重构 $A\approx USV^T$ 时会失败。

\subsection{改变迭代方法}

原来的方法每一轮都扫描所有子矩阵，其中大量 $1\times1$ 子矩阵已经收敛，但仍会被反复扫描。我的实现改成：从任务池中取出一个非 $1\times1$ 子矩阵，在 worker 内部连续执行 bulge chase，直到它可以再次分裂或全部收敛，再返回 master。

worker 的逻辑可以概括为：
\begin{lstlisting}[language=C++]
for (int iter = 0; iter < max_iter; ++iter)
{
    cleanup local bidiagonal matrix;
    handle zero diagonal cases;
    if (can_split || all_converged)
        break;
    do one bulge chase step on local active block;
}
\end{lstlisting}

这个思路的依据是：每个活动块在上对角断开后与其他块相互独立。对某一个活动块连续做 GKH 迭代，不会影响其他已经断开的块。因此将活动块作为任务单位分配给 worker，在实现上是比较自然的。

\section{实验设计与测试方法}

测试时固定随机种子基值为 \texttt{20260408}，这样不同进程数下输入矩阵保持一致，方便比较结果。测试样例包括固定值 $5\times5$、随机 $8\times8$、近秩亏损 $10\times8$、随机 $10\times8$ 和随机 $1000\times1000$。其中小规模矩阵主要用来检查程序是否正确，大规模矩阵主要用来观察 MPI 并行后的运行时间变化。

本文中把 1 进程 MPI 运行结果作为基线进行比较。这里的 1 进程版本仍然运行在 MPI 框架下，所以它不等同于完全独立的纯串行程序，但可以用来观察进程数从 1 增加到 2、4、8，以及使用 2 节点后对程序性能的影响。

正确性检查主要包括以下几项：
\begin{itemize}
  \item 是否收敛，即 \texttt{converged=yes}；
  \item 重构误差 $\|A-USV^T\|_F$ 和相对重构误差；
  \item $U,V$ 的正交误差；
  \item $S$ 的非对角元素是否已经清零；
  \item 奇异值是否非负，并且是否按降序排列。
\end{itemize}

如果只看运行时间而不检查这些误差，SVD 结果可能并不可靠。因此本实验在每个测试样例后都输出了正确性指标，只有所有指标满足阈值时才认为该样例通过。

\section{实验结果与性能分析}

\subsection{正确性分析}

实验数据表明，在 1、2、4、8 进程（单节点）及 2 节点 8 进程配置下，全部 5 个测试样例均通过，结果均为 \texttt{PASS}。所有样例都满足 \texttt{converged=yes}、\texttt{diagonal structure error=0}、\texttt{descending order error=0}、\texttt{nonnegative diagonal=yes}。

以 $1000\times1000$ 随机矩阵为例，五组实验的相对重构误差均为 $3.56975\times10^{-13}$，$U$ 的正交误差约为 $2.34328\times10^{-13}$，$V$ 的正交误差约为 $2.34008\times10^{-13}$。这些误差都处在比较小的数量级，说明 MPI 并行后没有破坏数值稳定性。对 SVD 来说，重构误差和正交误差是比较关键的指标，如果这两个指标变差，即使程序变快也没有太大意义。

\subsection{分阶段分析}

从分阶段耗时看，上二对角化和 GKH 迭代大约各占一半时间。以 1 进程为例，上二对角化耗时约 55969.9 ms（占 52.6\%），GKH 迭代耗时 50484.2 ms（占 47.4\%）。这与纯串行版本中 GKH 占绝对主导（约 96\%）的情况不同。MPI 版本中，上二对角化阶段由于每一步 Householder 更新后都需要通过 \texttt{MPI\_Allreduce} 同步向量并同步矩阵块，通信开销大幅增加了该阶段的耗时，使其成为与 GKH 相当的瓶颈。即使在 4 进程下，上二对角化为 70679.8 ms，GKH 为 58604.3 ms，两阶段仍然大致相当。

上二对角化阶段的并行加速效果为负。1 进程时上二对角化为 55969.9 ms，4 进程时反而增加到 70679.8 ms，8 进程时为 65361.0 ms。主要原因是每一步 Householder 更新后都需要同步矩阵数据。虽然每个进程可以分担一部分行更新，但 \texttt{MPI\_Allreduce} 和同步矩阵块的成本随进程数增加而增长，同步等待时间也相应增加。对于 $1000\times1000$ 这样的规模，通信开销已经超过了计算分工带来的收益。

GKH 阶段同样没有获得有效加速。1 进程时 GKH 耗时 50484.2 ms，2 进程时减少到 46313.5 ms，但 4 进程时增加到 58604.3 ms，8 进程时为 53702.9 ms。活动块分裂存在不均衡问题，大量情况下只有一个很大的未收敛块，其他进程即使存在也没有足够任务可做。此外，子矩阵任务的发送和回收也带来额外通信开销，导致该阶段的并行扩展性受到限制。

\subsection{为什么增加进程数未能提升性能}

我认为增加进程数后性能反而下降主要有以下原因：
\begin{enumerate}
  \item \textbf{上二对角化通信开销过大。} 每一步 Householder 变换都需要 \texttt{MPI\_Allreduce} 汇总局部结果，并同步更新后的矩阵块。进程数越多，每次 Allreduce 的同步等待时间越长，矩阵块同步的数据量也越大。4 进程和 8 进程时，上二对角化耗时反而从 55969.9 ms 增加到 70679.8 ms 和 65361.0 ms，说明通信开销已经完全超过了并行计算的收益。
  \item \textbf{GKH 阶段任务并行度有限。} 活动块的规模由数值收敛过程决定，很多情况下只有少数几个甚至一个大的未收敛块。多进程无法从少量任务中获得并行收益，反而因任务分配和结果回收的通信而增加开销。
  \item \textbf{数据拷贝与传输开销大。} 子矩阵任务不仅包含 $B$ 子块，还包含 $U,V$ 的列数据。对于大矩阵，$U,V$ 列的传输量并不小，每次任务分配和回收都需要大量数据搬移。
  \item \textbf{内存带宽竞争。} 多进程同时运行时，每个进程都有自己的矩阵副本，会带来更大的内存占用和访存压力，尤其是在单节点上多个进程竞争同一组内存通道时更为明显。
  \item \textbf{串行部分限制。} master 的任务池管理、结果写回、最终排序和正确性检查等部分仍然主要在 rank 0 上完成，无法通过增加进程来加速。
\end{enumerate}

2 节点 8 进程的配置（加速比 1.01）与 1 进程基本持平，说明跨节点通信虽然减轻了单节点的内存带宽竞争，但网络延迟和跨节点数据传输的开销又抵消了这一优势。综合来看，本 MPI 实现的通信模式不适合通过简单增加进程数来获得性能提升。

\subsection{小规模样例分析}

小规模矩阵如 $5\times5$、$8\times8$、$10\times8$ 的耗时都在毫秒甚至亚毫秒级（1 进程的 $5\times5$ 和 $8\times8$ 因 MPI 初始化开销显示为 233.95 ms 和 82.08 ms，实际计算量极小）。在这些测试中，进程数增加并不一定更快。由于矩阵太小，进程调度和通信的固定开销占比很大，因此小规模数据不能很好体现 MPI 的优势。它们更适合作为正确性测试。

\section{MPI 与多线程结合说明}

在本次 SVD 实验中，MPI 属于多进程并行方式，OpenMP 和 Pthread 属于多线程并行方式。二者的区别在于：MPI 的不同进程之间拥有独立的地址空间，数据不能直接共享，必须通过 \texttt{MPI\_Bcast}、\texttt{MPI\_Send}、\texttt{MPI\_Recv}、\texttt{MPI\_Allreduce} 等通信接口进行交换；而多线程是在同一个进程内部创建多个线程，线程之间共享内存，因此更适合对同一块矩阵数据进行细粒度并行更新。

将 MPI 与多线程结合，可以理解为一种“进程级并行 + 线程级并行”的混合并行模式。通常可以把整个程序先用 MPI 划分成多个进程，每个进程负责一部分任务或一部分数据；然后在每个 MPI 进程内部再使用 OpenMP 或 Pthread 创建多个线程，对本进程负责的数据块进行进一步加速。这样既能利用多节点或多进程的计算资源，也能利用单个节点内部的多核 CPU 资源。

在 SVD 算法中，主要计算过程可以分成两个阶段：第一阶段是 Householder 上二对角化，第二阶段是 Golub-Kahan 隐式 QR 迭代。对于上二对角化阶段，矩阵更新涉及大量向量点积和行列更新操作，计算量较大，并且很多行或列的更新相互独立，因此适合在线程内部并行。例如 MPI 先按行把矩阵划分给不同进程，每个进程内部再用 OpenMP 对自己负责的行更新循环进行并行。这样外层 MPI 负责不同进程之间的任务分配和归约，内层 OpenMP 负责本地矩阵块的快速计算。

对于 GKH 迭代阶段，算法会不断对上二对角矩阵中的活动块进行分割和迭代。这里 MPI 可以采用主从式结构：主进程维护任务池，把尚未收敛的非 $1\times1$ 子块分发给 worker 进程；worker 进程拿到子块后进行若干步 bulge chasing 迭代，直到该子块可以继续分裂或者收敛，再把结果返回主进程。进一步地，在每个 worker 进程内部，还可以使用多线程并行处理局部矩阵更新，例如对 $U$、$B$、$V$ 的行列旋转更新进行线程级并行。

这种混合并行方式的优点是并行层次更加充分。MPI 适合处理粗粒度任务，比如不同矩阵块之间的划分、不同活动子块之间的任务调度；多线程适合处理细粒度任务，比如局部矩阵块内部的循环计算、向量内积、矩阵行列更新等。相比单纯使用 MPI，混合方式可以减少进程数量过多带来的通信开销；相比单纯使用多线程，混合方式又可以突破单机共享内存的限制，更适合在多节点环境下扩展。

但是 MPI 与多线程结合也会带来额外问题。首先是通信和同步开销会增加。MPI 进程之间需要显式通信，而线程内部也需要同步，如果两层并行划分不合理，可能会出现通信时间和等待时间过高的问题。其次是负载均衡问题。SVD 的 GKH 迭代中，不同活动子块的收敛速度可能不同，有些子块很快收敛，有些子块需要多次迭代，因此如果任务分配不均匀，就会导致部分进程或线程空闲。再次是内存带宽竞争问题。矩阵计算中大量操作都需要访问内存，当线程数增加到一定程度后，性能可能不再提升，甚至下降。

结合本次实验数据也能看到这一点。对于 $1000\times1000$ 矩阵，1 进程总耗时约为 106454.1 ms，2 进程约为 98063.7 ms，有轻微加速；但 4 进程时总耗时变为 129284.1 ms，8 进程时为 119063.9 ms，性能反而下降。这说明当进程数量增加时，MPI 通信和同步的开销超过了并行计算的收益，导致并行效率下降甚至为负。因此 MPI 与多线程结合时，并不是线程和进程越多越好，而是需要根据矩阵规模、机器核心数、通信代价和算法瓶颈选择合适的并行粒度。

从实现角度看，本实验中的 MPI 版本已经体现了与多线程思想结合的基础。上二对角化阶段使用 MPI 按行划分任务，并通过 \texttt{MPI\_Allreduce} 汇总各进程的局部计算结果；GKH 阶段采用主从式任务池结构，由 rank 0 进程负责分发活动子块，worker 进程负责局部迭代计算。若进一步扩展为 MPI + OpenMP 混合版本，可以在每个 MPI worker 内部对矩阵更新循环加入 OpenMP 并行区域，例如对行更新、列更新和向量点积循环使用 \texttt{\#pragma omp parallel for}。这样形成“MPI 负责进程间分块，多线程负责进程内计算”的结构。

总体来说，MPI 与多线程结合的核心思想是：MPI 用来进行较大粒度的数据划分和任务调度，多线程用来加速每个进程内部的局部计算。在 SVD 实验中，这种方式可以用于 Householder 双对角化和 GKH 迭代两个阶段。合理设计时，它能够同时利用多进程和多核 CPU 的优势；但如果划分粒度过细或线程数过多，也可能因为通信、同步和内存带宽竞争导致加速比不理想。因此混合并行的关键不只是“加更多并行”，而是要在计算量、通信量和同步开销之间取得平衡。

\section{复杂度与通信开销分析}

对于 $m\times n$ 且 $m\ge n$ 的矩阵，Householder 上二对角化的主要计算复杂度约为
\[
O(mn^2).
\]
如果只考虑理想计算划分，$P$ 个进程可以把部分行更新分摊为
\[
O\left(\frac{mn^2}{P}\right).
\]
但是每一步都需要归约向量或同步矩阵块。粗略估计第 $k$ 步需要归约长度为 $n-k$ 的向量，并同步规模约为 $(m-k)(n-k)$ 的数据，所以通信量可以写成
\[
\sum_{k=0}^{n-1} O(n-k) + \sum_{k=0}^{n-1}O((m-k)(n-k)).
\]
因此在简单实现中，通信量也会非常可观，这解释了上二对角化阶段加速有限。

GKH 阶段若对一个大小为 $s$ 的活动块做一次 bulge chase，计算量约为 $O(s^2)$，因为每次 Givens 旋转要更新 $B$ 以及 $U,V$ 的相关列。如果活动块能够均匀分裂成多个子块，则任务池可以提供并行性。但如果始终存在一个大块，则并行效率会退化。通信方面，一个子任务至少要传输
\[
O(s^2) + O(ms) + O(ns)
\]
的数据，分别对应 $B$ 子块、$U$ 列和 $V$ 列。当 $m,n$ 很大时，$U,V$ 的列数据传输是主要成本。

\section{Profiling 与通信开销分析}

本实验对 MPI 版 SVD 程序进行了 profiling。程序主要分为两个阶段：第一阶段是基于 Householder 变换的上二对角化，第二阶段是基于 Golub-Kahan 隐式 QR 的 GKH 迭代。实验矩阵规模为 $1000\times1000$，随机种子基值为 \texttt{20260408}。

从实验结果看，1 进程时总耗时为 106454.1 ms，其中上二对角化耗时 55969.9 ms，GKH 迭代耗时 50484.2 ms。2 进程时总耗时下降到 98063.7 ms，加速比为 1.09，有一定改善。但是当进程数增加到 4 时，总耗时变为 129284.1 ms，加速比仅为 0.82；8 进程时总耗时为 119063.9 ms，加速比为 0.89。2 节点 8 进程配置总耗时为 105817.4 ms，加速比为 1.01，与 1 进程基本持平。这些数据说明进程数增加后并没有带来更好的性能，反而因通信开销而下降。

从阶段占比看，上二对角化阶段约占总时间的 53\%，GKH 迭代约占 47\%，两个阶段都是主要性能瓶颈。与纯串行版本中 GKH 占 96\% 以上相比，MPI 版本的上二对角化因频繁的 \texttt{MPI\_Allreduce} 和矩阵同步操作，通信开销大幅增加了该阶段耗时。因此，优化上二对角化阶段的通信模式对整体性能的提升与优化 GKH 阶段同等重要。

从实现角度分析，上二对角化阶段每一步 Householder 变换都需要进行局部计算和全局同步，代码中多次使用 \texttt{MPI\_Allreduce} 汇总向量和矩阵更新结果。该方式实现比较直接，但通信开销极大。随着进程数增加，全局通信的同步成本显著增长，4 进程和 8 进程时上二对角化耗时反而从 55969.9 ms 增加到 70679.8 ms 和 65361.0 ms。GKH 阶段中，rank 0 作为 master 维护任务池，worker 进程通过 \texttt{TAG\_REQUEST} 请求任务，通过 \texttt{TAG\_RESULT} 返回计算结果。该结构能够实现动态任务分配，但 rank 0 也会成为一定的调度中心，且活动块数量不足时无法充分利用所有 worker。

综合来看，MPI 版 SVD 程序在 2 进程时可以获得有限加速，但 4 进程及以上性能反而下降。主要原因是上二对角化阶段的通信开销过于严重，以及 GKH 阶段的任务并行度有限。后续优化可以从减少 \texttt{MPI\_Allreduce} 次数、改进矩阵数据分布以降低同步数据量、增大任务粒度、对 GKH 活动块进行更细致的负载均衡，以及结合 OpenMP 做进程内并行等方向继续改进。

\section{总结与改进方向}

本实验完成了 SVD 算子的 MPI 并行实现。程序先使用 Householder 变换将矩阵化为上二对角形式，然后使用 Golub-Kahan 隐式迭代求奇异值，并在过程中累积 $U,V$ 矩阵。根据实验要求，我实现了 GKH 阶段的主从式任务池结构，并把迭代方式改为“取出非 $1\times1$ 子矩阵后连续迭代到可分裂再返回”。同时，在上二对角化中的连续向量点积和更新部分合并了 SIMD 优化。

实验结果显示，1、2、4、8 进程及 2 节点 8 进程下所有测试样例均通过，重构误差和正交误差保持在较小数量级，说明程序正确性较好。性能方面，$1000\times1000$ 随机矩阵在 2 进程下相对 1 进程约有 1.09 倍轻微加速，但 4 进程和 8 进程性能反而下降（加速比分别为 0.82 和 0.89），2 节点 8 进程与 1 进程基本持平（加速比 1.01）。主要原因是上二对角化阶段通信开销过于严重，以及 GKH 阶段活动块并行度有限、MPI 通信和数据拷贝开销较大。

总体来看，这次实验完成了 MPI SVD 的基本要求。虽然加速效果非常有限甚至为负，但通过实验可以看出，SVD 这种数值算法在 MPI 中并不是简单增加进程就一定更快。尤其是上二对角化阶段的频繁同步和 GKH 迭代阶段的任务不均衡，都会严重影响最终性能。这也是本次实验中我感觉最明显的一点。

后续如果继续优化，可以考虑以下几个方向：
\begin{itemize}
  \item 减少 $U,V$ 列数据的频繁传输，降低子任务通信量；
  \item 调整任务粒度，避免任务太小导致通信开销过高；
  \item 在单个大活动块内部继续做更细粒度并行，减少 worker 等待；
  \item 尝试 MPI 与 OpenMP 的混合并行，让每个 MPI 进程内部再使用多线程；
  \item 对矩阵存储和访问方式做进一步优化，减少 cache miss 和内存带宽压力。
\end{itemize}
